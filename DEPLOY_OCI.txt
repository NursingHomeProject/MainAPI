PARTE 1 — ABRIR AS PORTAS NA OCI (painel web)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Sem isso, ninguém de fora consegue acessar o sistema.

1. Acesse console.oracle.com
2. Vá em: Networking > Virtual Cloud Networks > sua VCN
3. Clique em "Security Lists" > "Default Security List"
4. Clique em "Add Ingress Rules" e adicione as seguintes regras:

   Regra 1 — Frontend (porta 80):
     Source CIDR: 0.0.0.0/0
     IP Protocol: TCP
     Destination Port Range: 80

   Regra 2 — Backend (porta 8000):
     Source CIDR: 0.0.0.0/0
     IP Protocol: TCP
     Destination Port Range: 8000

   Regra 3 — SSH (se ainda não existir):
     Source CIDR: 0.0.0.0/0
     IP Protocol: TCP
     Destination Port Range: 22

ATENÇÃO: O OCI tem duas camadas de firewall. Além das regras acima,
você também precisa liberar as portas no firewall da própria VM (Parte 2).

PARTE 2 — CONFIGURAR O FIREWALL DA VM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Conecte na VM via SSH:
  ssh ubuntu@129.148.49.83

Libere as portas no firewall interno da VM:

  $ sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT
  $ sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 8000 -j ACCEPT
  $ sudo netfilter-persistent save

Se o comando netfilter-persistent não existir, instale com:
  $ sudo apt install iptables-persistent -y

PARTE 4 — CONFIGURAR O POSTGRESQL NA VM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  # Iniciar o serviço
  $ sudo systemctl start postgresql
  $ sudo systemctl enable postgresql

  # Criar o banco e definir a senha do usuário postgres
  $ sudo -u postgres psql

  Dentro do psql, execute:
    ALTER USER postgres PASSWORD 'ESCOLHA_UMA_SENHA_FORTE';
    CREATE DATABASE casa_assistencial;
    \q

  IMPORTANTE: Anote a senha que você escolheu. Ela vai no .env do backend
  (campo DATABASE_URL). Guarde também no arquivo SEGREDOS.txt da sua máquina.

PARTE 7 — CONFIGURAR O SUPERVISOR (manter o backend rodando)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

O Supervisor garante que o backend reinicia automaticamente se cair.

  $ sudo nano /etc/supervisor/conf.d/casa-backend.conf

  Cole o conteúdo:

  --------------------------------------------------------------------------
  [program:casa-backend]
  command=/home/ubuntu/casa/backend/venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
  directory=/home/ubuntu/casa/backend
  user=ubuntu
  autostart=true
  autorestart=true
  stderr_logfile=/var/log/casa-backend.err.log
  stdout_logfile=/var/log/casa-backend.out.log
  environment=HOME="/home/ubuntu",USER="ubuntu"
  --------------------------------------------------------------------------

  Ativar:
  $ sudo supervisorctl reread
  $ sudo supervisorctl update
  $ sudo supervisorctl start casa-backend

  Verificar se está rodando:
  $ sudo supervisorctl status casa-backend

  Deve mostrar: casa-backend   RUNNING   pid XXXXX, uptime 0:00:XX

  Ver logs em tempo real:
  $ sudo tail -f /var/log/casa-backend.out.log

      server_name 129.148.49.83;

      root /home/ubuntu/casa-frontend;

  $ sudo ln -s /etc/nginx/sites-available/casa-frontend /etc/nginx/sites-enabled/

  $ sudo nginx -t
  $ sudo systemctl restart nginx
  $ sudo systemctl enable nginx

PARTE 10 — PROBLEMAS COMUNS E SOLUÇÕES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PROBLEMA: "Failed to fetch" no login
  CAUSA: Backend não está acessível ou CORS bloqueando.
  VERIFICAR:
    - $ curl http://129.148.49.83:8000/docs  (deve retornar HTML)
    - $ sudo supervisorctl status casa-backend  (deve estar RUNNING)
    - Portas 80 e 8000 abertas no painel OCI (Parte 1)
    - Portas liberadas no firewall da VM (Parte 2)

PROBLEMA: "E-mail ou senha inválidos" mesmo com credenciais corretas
  CAUSA: Banco vazio (migrations não rodaram) ou senha diferente do .env.
  VERIFICAR:
    - $ cd /home/ubuntu/casa/backend && source venv/bin/activate
    - $ alembic upgrade head  (rodar novamente, deve mostrar "já na versão atual")
    - Confirmar que ADMIN_PASSWORD no .env bate com a senha que você está usando
    - Se necessário, reiniciar o backend: $ sudo supervisorctl restart casa-backend

PROBLEMA: Página em branco ou erro 404 no frontend
  CAUSA: Nginx não configurado corretamente ou pasta dist não enviada.
  VERIFICAR:
    - $ ls /home/ubuntu/casa-frontend/index.html  (deve existir)
    - $ sudo nginx -t  (deve mostrar "syntax is ok")
    - $ sudo systemctl status nginx

PROBLEMA: Erro de CORS no console do navegador
  CAUSA: A origem do frontend não está na lista CORS_ALLOW_ORIGINS do backend.
  SOLUÇÃO: Editar o .env do backend na VM e adicionar a origem correta:
    CORS_ALLOW_ORIGINS=["http://129.148.49.83","http://SEU_DOMINIO_SE_TIVER"]
  Depois reiniciar: $ sudo supervisorctl restart casa-backend

PROBLEMA: Banco de dados não conecta (connection refused)
  CAUSA: PostgreSQL não está rodando.
  SOLUÇÃO:
    - $ sudo systemctl start postgresql
    - $ sudo systemctl enable postgresql

PROBLEMA: O admin não foi criado automaticamente
  CAUSA: Erro no banco durante a inicialização.
  VERIFICAR OS LOGS:
    - $ sudo tail -50 /var/log/casa-backend.out.log
  SOLUÇÃO: Corrigir o erro apontado no log e reiniciar o backend.
